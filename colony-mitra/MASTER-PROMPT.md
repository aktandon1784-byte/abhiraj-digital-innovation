## 1. Identity: how the app knows who is committee and who is a resident

- There is **one login** for everyone: mobile number + OTP (email OTP optional).
  There is no separate "admin login" button.
- After OTP, the **server** looks up the verified phone number in the colony's `members`
  table. The role stored there decides what opens:
  - `admin` (committee: अध्यक्ष, उपाध्यक्ष, सचिव, सह-सचिव, कोषाध्यक्ष, सदस्य, सलाहकार) → full committee view
  - `resident` (linked to one house) → own profile only
  - not listed, or `blocked` → nothing opens; the person may send a **join request**
- Every data read/write is re-checked by the database against this table. Editing the app
  code on a phone cannot grant admin rights.
- Chain of trust:
  1. App owner (Abhiraj Digital) creates a colony with the first admin (usually अध्यक्ष).
  2. **Only अध्यक्ष or सचिव** (or the app owner) can add, remove or change committee/admin
     members. Other committee members can add/edit residents only.
     (Bootstrap: if a colony has no admin with post अध्यक्ष/सचिव, any admin may set one.)
  3. Committee adds residents (phone + house).
- A colony can never be left without an admin.
- Every change to the members list is written to an **audit log** (who, when, what),
  visible to all committee members.
- A member can be **blocked** (lost phone) — their access stops immediately.
- The first person to press "मैं इस ऐप का मालिक हूँ" after a fresh server setup becomes the
  app owner, so the owner must do this immediately after setup.

## 2. What each role sees

| Data | Filled by | Resident (self) | Other residents | Committee |
|---|---|---|---|---|
| Own profile, house, family | resident (family) / committee (house identity) | view + edit family | ✗ | ✓ |
| Tenants of own house (full biodata + photos/docs) | resident | view + edit | ✗ | ✓ + verify |
| Own maintenance, dues, receipts | committee / payment | view | ✗ | ✓ |
| Own complaints | resident | ✓ | ✗ | ✓ + status/reply |
| Messages to own house | committee | ✓ | ✗ | ✓ |
| Notices, polls, committee list, services, CCTV status, gallery, fees/चंदा list | committee | view | view | ✓ |
| Colony fund **totals only** (income, expense, balance) | system | view | view | full cash book |
| All houses, all tenants, all dues, vehicles, members | — | ✗ | ✗ | ✓ |

Wrong-parking complaint: a resident may enter a vehicle number; only the committee sees the
matched owner.

## 3. Tenant biodata (resident fills from own profile)

Any number of tenants per house. Fields: photo, name, father/husband name, age, mobile,
permanent address (village/city, district, state), family members living with them,
**Aadhaar last 4 digits only + masked Aadhaar copy** (never the full 12-digit number),
workplace name and address, work ID card photo, tenancy start date, police verification
status + copy, emergency contact, **tenant consent checkbox (required)**.
Committee marks each tenant "जाँच हो गई ✔". A resident cannot set this flag.
When a tenant leaves, the resident marks "घर छोड़ दिया". After 90 days, the tenant's documents
(photos, Aadhaar copy, ID, police copy) are deleted the next time a committee member opens the app.
App cannot do official Aadhaar verification (needs UIDAI licence); the committee checks documents
manually; police verification is the real check.

## 4. Payments to the committee

- Committee creates **fees / चंदा** (monthly maintenance is built in; others like नवरात्रि गरबा,
  अम्बेडकर जयंती, गुरु घासीदास जयंती, होली मिलन): title, fixed amount or voluntary (minimum),
  last date, open/closed.
- Residents see their own dues and pay by **UPI directly to the committee's UPI ID** (QR / UPI app
  link, zero fee). The resident submits the UTR; the committee confirms; a receipt is created and the
  amount enters the cash book.
- **Razorpay per colony (phase 2, not built yet):** only with the committee's own Razorpay account
  (society bank account, PAN, KYC). Keys stay server-side. Never use Abhiraj Digital's own Razorpay
  account for colony money.

## 5. Complaints and messages

- Resident complaint categories: घर की लाइट / बिजली, स्ट्रीट लाइट, नाली सफ़ाई, कचरा गाड़ी, CCTV,
  पानी, सड़क, पार्किंग, सुरक्षा, अन्य; with description and optional photo.
  Status: नई → काम चल रहा है → हल हो गई, plus committee reply. Visible only to that house and committee.
- Committee "संदेश भेजें": to all houses, houses with dues, or selected houses; types: सूचना,
  बकाया याद दिलाना, जाँच / पूछताछ, अन्य. Delivered inside the app immediately. WhatsApp: one-by-one
  "WhatsApp पर भेजें" links now; automatic bulk WhatsApp/SMS only after a WhatsApp Business / SMS
  provider is connected (per-message cost).

## 7. Technical design (current implementation)

- Static PWA (`public/colony-mitra/app`), backend Supabase (Postgres + Auth + Storage + Realtime).
- `colony-mitra/supabase/schema.sql` (idempotent):
  - `members`: `role`, `post`, `house_id`, `blocked`; guard trigger for admin changes; audit table `member_audit`.
  - `docs` (JSON documents per colony/collection/id) with a server-computed `house_id`.
    Read rule: admin OR public collection OR own house's private record OR own created record.
  - Public collections: config, notices, polls, pollvotes, services, svcvotes, committee, cameras,
    cctvlog, gallery, fees, inbox (broadcast only).
  - Private per-house collections: houses, payments, payclaims, complaints, vehicles, tenants,
    feepay, inbox (per house). Admin-only: expenses and anything not listed.
  - Server triggers force safe values for residents (complaint status `new`, claim status `pending`,
    tenant `verified` cannot be set by residents).
  - RPCs: `my_colonies`, `colony_summary` (totals only), `my_house_update` (whitelisted fields),
    `request_join` / `join_requests`, `create_colony`, `claim_platform_admin`, `doc_patch`.
  - Storage bucket `colony`: `<colony>/<file>` = colony-wide (admin upload);
    `<colony>/h/<house>/<file>` = that house + committee only.
- Demo backend in `colony-mitra/demo/backend.js` mirrors the same rules; `node colony-mitra/build-demo.mjs`
  regenerates `public/colony-mitra/demo.html`.
